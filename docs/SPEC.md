# FilePilot v1.0 需求规格（P0）

> 目标：一个人 + AI agent，4–6 周交付。P0 是"没有它就不叫 MVP"的最小集合。

## 功能需求

### 1. 文件夹监控
- 用 `notify` crate 监听用户选定的文件夹（默认：下载文件夹），文件新增/稳定后触发规则。
- 防抖：文件写入完成（大小稳定 N 秒）后再处理，避免处理一半的下载文件。
- 跳过临时文件：`.tmp`、`.part`、`.crdownload` 等。

### 2. 可视化 if-then 规则编辑器
- 卡片式 UI：IF 条件组 + THEN 动作组，点选式配置，不写脚本。
- 条件（4 种）：扩展名 / 文件名关键词（含中文）/ 文件大小 / 创建日期。
- 动作（4 种）：移动 / 复制 / 重命名（支持变量如日期）/ 移入回收站。
- 每条规则独立选择自动整理或仅手动；新规则默认仅手动，既有规则配置不变。
- 全局暂停/恢复只控制自动监控，不改变单规则的自动设置；手动规则可独立预览和执行。
- 规则列表支持搜索和自动/手动筛选；规则模板有独立导航入口。
- 路径支持输入/粘贴及原生文件夹选择；扩展名支持分组多选、搜索和自定义。
- 保存时以红框和字段旁提示标出全部缺失或不合法的必填项，并定位到首个错误；修正后即时清除该项错误。
- 新建/编辑规则弹窗点击外侧空白处不关闭，避免误点击丢失草稿。

### 3. dry-run 预览（默认开启）
- 新规则默认仅手动；保存后点击“预览整理”，扫描来源文件夹，展示文件、动作和目标位置。
- 手动点“确认整理”后才执行；自动整理由用户主动开启单规则自动开关及全局监控。

### 4. 操作日志 + 一键撤销
- 每次执行写 JSON 日志：源路径 → 目标路径 → 时间 → 规则名。
- 托盘菜单"撤销上次整理"一键回滚；日志页可查看历史、单条撤销。
- 删除动作强制进回收站，绝不彻底删除。

### 5. 全中文界面
- 全中文；浅色、深色及跟随系统在设置中选择。设计以 `design/UI_FINAL.md` 为准。
- 默认窗口 1120 × 700 逻辑像素，最小 960 × 600，居中且可调整大小。
- 规则页标题、新建按钮和搜索筛选栏固定，仅规则列表滚动。
- 左下角只显示自动整理状态、启停及实际异常入口；历史结果留在操作记录页。

### 6. 开机自启 + 托盘常驻
- 可选开机自启；最小化到托盘；托盘菜单：打开主界面 / 暂停监控 / 撤销上次整理 / 退出。

### 7. 分发
- NSIS 安装包 + 便携版 zip，GitHub Release 自动发布。

## 非功能需求

- 纯本地运行，不联网，无遥测。
- 安装包体积目标 < 20MB；常驻内存 < 100MB。
- 误删防护：dry-run 默认开、回收站兜底、首次运行建议用测试文件夹。
- 明确不做（P0）：子文件夹递归监控、PDF 内容识别、复杂嵌套逻辑、云同步、多语言、代码签名（v1.0 先无签名发布）。

## 技术栈

Tauri 2（前端 React+TS，后端 Rust）。文件监控与规则引擎在 Rust 侧实现，通过 Tauri command 暴露给前端。
