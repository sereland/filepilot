# 压缩包更新与整包撤销

更新日期：2026-10-11。

## 用户配置

执行动作选择“移动并解压到”，选择专用目标文件夹，再选择保留方式：

- **保留全部**：每个 ZIP 单独处理，ZIP 和解压目录使用同一名称，冲突时一起加编号。
- **只保留最新一份**：同组 ZIP 按修改时间保留最新一份，目标固定为 `包名.zip` 与 `包名/`。浏览器的尾部下载编号，如 `(4)` 或 ` (4)`，不作为版本号。其他包名仍是独立组。

例如：来源为下载目录，扩展名 ZIP，文件名包含 filepilot，动作“移动并解压到 D:\Builds\FilePilot”，保留方式“只保留最新一份”。

新动作包含移动、解压、旧项暂存与备份清理，初版作为规则的唯一动作，不能与其他动作混用。仅支持普通 ZIP；解压后保留原包内部目录结构。

## 预览与选择

- 同组五个 ZIP 作为一项整理，显示将保留的新 ZIP、解压目录，以及暂存的四个旧下载包。
- 首次接管目标目录时，列出同组名称的已有 ZIP、解压目录（含下载编号版本）。它们随本次更新一起暂存，其他文件不动。
- 更新组整体勾选或排除，不能只移除组内一个旧包；提交名单包含该组所有来源路径。
- 后端重新扫描时先过滤明确选中的来源，再分组，预览后新增的下载不进入本次手动执行。
- 预览记录来源与旧目标内容摘要，执行前重新核对；内容或文件集合变化时要求重新预览。
- 同组最新 ZIP 修改时间相同但内容不同，无法可靠选出最新版本，提示改用保留全部或移走旧包。
- 来源与目标不能是同一目录；新动作不跟随符号链接或目录联接。

## 执行和备份

1. 在目标内的应用管理目录准备新包副本并解压，检查路径、重复条目和 CRC。
2. 解压完成后，把目标旧包、旧目录及同组选中的旧下载包移入本次撤销备份。
3. 移动新 ZIP，发布新解压目录，保留固定目标名称。
4. 成功发布并持久化本次记录后，上一轮操作的更早备份进入系统回收站；其历史记录仍在，但不再提供一键撤销。

管理目录为目标中的 `.filepilot-backups`。首次接管的旧状态可能包含多份 ZIP 和目录，它们属于同一份撤销备份。没有后续成功更新时，备份不按天数过期。更早备份回收失败时保留数据并记录警告，不能把已经成功的更新报成失败。

更新失败时回滚已经移动的内容，保留原版本；如果恢复路径被外部文件占用或内容变化，停止并报告备份位置。失败后的同组来源暂时跳过自动处理，修改文件或手动预览确认后再尝试，避免文件回退导致反复触发。

## 撤销

- 接入“撤销上次整理”，以整包为单位恢复旧 ZIP、旧目录及旧下载包，把新 ZIP 返回实际来源。
- 不覆盖已经被重新占用的来源路径。新 ZIP、新解压目录或备份内容变化时停止撤销。
- 当前 ZIP 与目录必须全部通过检查才开始恢复；恢复中失败时尝试放回当前版本。
- 撤销成功后，新生成的解压目录从应用管理目录清理；恢复文件的大小与精确修改时间持久化为自动整理保护状态。
- 手动执行、监控执行与撤销串行，保护状态在释放执行锁前登记。文件修改后解除自动跳过；显式手动确认不受跳过名单限制。
- 旧包更新的备份被后续成功更新清理后，不再沿历史连续撤销到更早版本。

## 实现边界与检查

- 使用 Rust `zip` 读取与解压，SHA-256 校验来源、旧目录、当前版本和备份。普通 ZIP 支持 stored/deflate；加密、符号链接、不安全 Windows 文件名、路径越界或重复路径拒绝处理。
- 单 ZIP 上限 100000 个条目、8 GB 解压内容；空 ZIP 拒绝替换旧版。
- 操作意图与进度写入持久日志，重启时恢复中断更新/撤销，继续完成旧备份回收，并补齐已成功但尚未写入 JSONL 的包更新记录。
- 文件监控防抖调整为 6 秒，覆盖现有 5 秒稳定检查，防止文件被过早扫描后永远漏处理。
- 旧四种动作、旧规则和旧操作记录保持可读取；本轮不扩展通用条件表达式，也不改变普通动作的重名保留策略。
- Windows 工作流运行全部核心测试后打包。浏览器组件检查与 Rust 核心测试不能替代原生 Tauri 安装包验收。

本轮验证：前端 TypeScript 与生产构建通过；Windows GNU 工具链下 47 项核心测试全部通过，覆盖分组、名称冲突、旧版恢复、文件占用、ZIP 校验、真实监控与中断恢复。浏览器使用正式组件检查规则配置、整组选择和历史提示。当前机器缺少 Tauri 依赖缓存，联网下载未获允许，桌面胶水层编译与原生安装包验收待 GitHub Actions 构建及安装后验证。

后续回收站修正：原有 `trash` 库的显示名称受隐藏扩展名影响，本机“显示扩展名”的测试未覆盖该差异。已使用回收站虚拟条目的 `System.FileName` 读取含扩展名的原始名称，并检查实际恢复路径；通过 `.lnk` 文件复现旧实现失败，新增带 id、旧记录无 id、恢复失败提示三项回归测试。本地 50 项核心测试通过，CI 配置分别在隐藏/显示扩展名下运行全套测试。

后续短路径修正：CI 的临时目录包含 `RUNNER~1` 这类 8.3 短名，回收站返回长目录名，纯字符串归一化仍无法匹配。Windows 路径比较现先规范化仍存在的路径或最近祖先，再接回已删除的文件名，兼容文件已回收、父目录尚在的状态。使用真实系统短名验证带 id 和无 id 两种恢复、缺失子目录及不同文件不混淆；旧代码在该用例失败，修复后本地 51 项测试通过。CI 强制要求该用例实际执行，测试卷不提供短名时明确失败。
