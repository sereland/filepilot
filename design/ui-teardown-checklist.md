# FilePilot UI Teardown 清单

> 目标：去掉"AI 感"，做到克制、精致、可信。依据：Fluent 2 官方 token（fluent2.microsoft.design）、
> Things 3 / Raycast 的设计纪律。先讨论再动手。

## 一、Token 体系（对着 Fluent 2 spec 落）

| 类别 | Fluent 2 规范值 | 我们现在 | 动作 |
|---|---|---|---|
| 间距 | 0/2/4/6/8/10/12/16/20/24/32（4px 基准） | 随意值较多（3px、7px、9px、14px…） | 全部收敛到 4px 倍数 |
| 圆角 | Small 2 / Medium 4（控件默认）/ Large 6 / XLarge 8（卡片常用）/ Circular（胶囊/头像）——React token ramp 里没有 12/16px 档 | 6/8/9/10/14 混用 | 控件 4px、卡片 8px 两档为主；弹窗若用 12px 属有意自定义（非 token，为与卡片拉开层级），需在评审时明确 |
| 字阶 | 标题 semibold / 正文 regular / 元信息 secondary 灰 | 大致有，但字重滥用（多处 700） | 见第三节 |
| 颜色 | 中性色干活，一个 brand 强调色；描边用 stroke token | accent 出现频率过高（tag、圆点、开关全是蓝） | 强调色只留给：主按钮、激活态、开关开态 |
| 阴影 | shadow2/4/8/16/28/64 分级；卡片用浅级 | 卡片阴影偏重且 hover 加深 | 卡片只用一级浅阴影，hover 不加深只换边框色 |
| 动效 | 50–500ms，ease 曲线；动效克制或没有 | 弹窗弹性曲线 cubic-bezier 带回弹、呼吸灯、视图位移 | 全部改为 150–200ms ease，删呼吸灯和回弹 |

## 二、删掉的"AI 感"元素

1. **品牌渐变磁贴** → 改为扁平单色小方块（或直接去掉色块，用字标 + 小图标）。
   AI 味来源：渐变 + 内阴影 + 光晕是生成式 UI 的标志性套路。
2. **规则卡片左侧状态色条** → 直接删掉（lee 点名）。
   状态改由"启用中/已停用"文字 + 开关本身表达，不再用颜色编码。
3. **监控卡呼吸灯动画** → 改为静态绿点。
4. **弹窗进入回弹动画** → 改为 150ms 淡入 + 轻微上移。
5. **规则编辑器的步骤序号 1-2-3** → 删掉。顺序在这里不承载真实含义（装饰性编号正是 AI 味来源之一），
   改为普通的 section 标题。
6. **毛玻璃 backdrop（blur 6px）** → 降为纯半透明遮罩（不模拟材质）。
   备注：Fluent 2 在 Windows 上对 transient surface 的正解其实是真 Mica/Acrylic 系统材质，而非 CSS blur 堆料；
   当前 6px backdrop-blur 是"假毛玻璃"，先砍掉；如需材质感，后续单独评估 Tauri 的 Win11 真 Mica 窗口背景。
7. **胶囊徽章泛滥** → "启用中/已停用"保留（有信息量），其余 tag 降级为纯文本颜色区分。

## 三、字阶规范（学 Things 3 的三级制）

- **一级**：页面标题 20px / 700（≈ Subtitle1）；卡片标题 14px / 600（Body1 字号 + Semibold）
- **二级**：正文 14px / 400（Body1，spec 默认字号；原清单写的 13px 不在字阶 ramp 里，若坚持用属有意自定义）
- **三级**：元信息 12px / 400，次要灰（文件夹路径、时间、副标题）
- 行高：正文 1.5，标题 1.25
- 禁止：正文用 700、到处加粗；中文标题字间距 letter-spacing 保持 0

## 四、对齐修复（lee 点名的两处 + 举一反三）

1. **页眉**：标题+副标题是两行文本块，按钮与之垂直居中 → 显歪。
   改法：按钮与第一行标题基线对齐（align-items: flex-start，按钮加与标题行同高的 padding 补偿），
   或副标题字号再小一档、弱化存在感。
2. **监控卡**：圆点相对两行文字垂直居中 → "监控中"与副标题视觉错位。
   改法：圆点与第一行文字首行基线对齐（align-self: flex-start + margin-top 补偿），副标题与"监控中"左对齐。
3. **全局检查**：所有"图标 + 两行文字"的组合，一律用首行基线对齐，不用块居中。
4. **侧边栏与内容区**：导航项文字、页面标题左对齐落在同一垂直线上（当前 sidebar padding 与 content padding 不一致）。

## 五、从 Mac 标杆偷的东西（可迁移的 80%）

**Things 3：**
- 三级字阶 + 大量留白：卡片内 padding 从 16px 提到 20px（XL token），行间距拉开；精致靠"少"不靠"加"
- 颜色只做层级（黑/灰/浅灰），不做装饰

**Raycast：**
- 列表行 8px 圆角 + 细分割线，hover 只换底色不加阴影
- 强调色只出现在可交互元素上（按钮、开关、激活态），静态信息一律中性色

**关于"Mac 光环"的结论：**
- 真实存在的 20%：Core Text 字体渲染、Retina 高分屏、系统强制统一的窗口边框——Windows 上补不回来，
  但可通过 Segoe UI Variable + 合适字号/字重逼近。
- 可迁移的 80%：克制、间距节奏、字阶——全是设计纪律，和系统无关，这份清单就是。

## 六、不动的部分

- icons.tsx 线性图标集（已经是对的）
- 操作记录按批次分组的时间线逻辑（信息架构没问题，只按新 token 微调样式）
- 整体信息架构（侧边栏两 tab、规则卡片、预览弹窗流程）

## 七、实施顺序（预计 1 次提交）

1. 重写 :root token（间距/圆角/字阶/颜色/阴影/动效）
2. 删装饰元素（色条、渐变磁贴、呼吸灯、步骤序号、重模糊）
3. 修两处对齐 + 全局基线对齐检查
4. 按字阶重排各处字号字重
5. 本地 tsc + vite build 验证（沙盒无头 Chromium 不可用，真机由 lee 验收）
