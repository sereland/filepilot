# 普通目录整理：第一阶段

## 用户操作

- 新建或编辑规则时选择“整理对象：文件 / 文件夹”。旧规则缺少该字段时默认按文件处理。
- 文件规则仍只扫描来源第一层的文件。文件夹规则只选择来源第一层的整个文件夹，不把内部文件拆成独立整理项。
- 文件夹条件支持名称关键词和创建时间；不使用文件扩展名或目录元数据大小作为条件。
- 每条文件夹规则执行一个动作：同盘移动、复制（可跨盘）、重命名、移入系统回收站。
- 同名目标加编号保留，目录名称中的点不作为扩展名拆分，例如 `project.v1 (1)`。预览显示本次实际目标。
- 重命名中的 `{name}` 是完整文件夹名称，支持日期和日期时间变量。非法名称或包含路径的格式拒绝执行。

## 执行与保护

- 目录及内部文件须静默超过 5 秒；内部有未完成下载文件、不能读取的内容或链接时暂不处理。隐藏的来源根项（包括应用管理目录）跳过；普通目录内部的隐藏文件仍作为内容复制。
- 不跟随符号链接或 Windows 目录联接，不允许把目录放进自身或子目录，也不合并、覆盖已存在的目标。
- 移动和重命名采用同盘目录重命名；跨盘失败时来源保持原样，提示改用复制。跨盘移动的复制/删除日志与中断恢复留待后续实现。
- 复制先准备唯一的 `.filepilot-copy-<UUID>` 临时目录，使用系统文件复制保留 Windows 文件属性及下载来源数据流，复制空子目录并保留文件修改时间。来源和副本内容校验一致后才发布目标；普通失败会清理本次临时目录。
- 目录计划携带内容校验，手动确认时重新核对预览，执行前再检查来源状态。目标被占用时停止并要求重新预览。
- 目录动作失败写入操作记录，展示具体原因；失败项不能撤销。卡片、预览和记录页区分文件和文件夹数量。
- 启用文件夹规则的来源监听内部变化，使用既有 6 秒防抖；只有文件规则的来源保持非递归监控。
- 已复制的来源、已移动或重命名的目标，以及撤销恢复的目录，保存包含内部条目名称、大小和修改时间的状态保护。未变化时跳过自动执行，避免复制、重命名及撤销的事件反馈；内部内容变化或手动确认后可继续处理。

## 撤销与边界

- 移动和重命名恢复原位置，原位置被占用时恢复到加编号的路径，不覆盖占用内容。
- 撤销复制将完整副本移入回收站，保留来源。目标目录内容已变化时拒绝撤销；移入回收站的目录沿用现有条目 id / 原路径恢复逻辑。
- 普通目录整理不生成 `.filepilot-backups` 版本备份，不识别或替换多版本目录。ZIP 更新的备份策略保持原状。
- 普通目录动作沿用普通文件动作的执行和 JSONL 记录流程，尚未增加 ZIP 更新级别的事务中断恢复。异常退出可能留下临时复制目录或尚未写入的操作记录；复制期间来源保持原样。

## 验证

新增核心集成测试覆盖旧规则兼容、浅层选择、内部写入与临时下载、点号名称、同名保留、占用原位置恢复、复制后变化保护、实际回收站恢复、非法名称、变化预览、选择排除、状态保护持久化、空目录、Windows 文件占用与目录联接、跨盘复制，以及真实子目录监控。前端校验测试覆盖合法文件夹规则、禁用条件/动作、多动作限制、必填提示和数量文案。

本地 69 项核心测试（51 项原有测试、18 项目录集成测试）、5 项前端校验测试及 TypeScript / Vite 构建通过，使用真实 Windows 回收站及 8.3 短路径临时目录，并验证只读文件、下载来源数据流和失败后的临时目录清理。浏览器检查正式规则编辑器的对象切换、条件/动作选项、目录重命名默认格式及必填高亮。离线 Tauri 检查因本机缺少 `tauri` 缓存未能完成；原生构建和安装包验收仍由 GitHub Actions 及安装后测试确认。
